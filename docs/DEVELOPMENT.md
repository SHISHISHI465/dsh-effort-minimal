# 开发与设计记录

本文保留首版实现的视觉、交互和排错细节。安装、兼容性与发布步骤以仓库根目录 README 和 docs/RELEASING.md 为准。

## 视觉状态（对齐 Codex 的两套观感）

| | 正常档 | 最高档（Ultra 状态，`data-spark="true"`） |
|---|---|---|
| 轨道 | 12px 高、本档色实心，两端胶囊圆头 | **青→紫渐变** |
| 档位点 | 随档位推进逐渐变实，当前档最亮 | **整体淡出**，位置交给粒子与圆点 |
| 粒子 | 无 | 填充段内一层白色粒子，横向缓漂 + 纵向浮沉 + 透明度呼吸（"悬浮在液体里"） |
| 圆点 | 白色大圆点（24px，比 12px 轨道粗一倍） | 同左，外加一层与本档色相同色的柔光 |

色相曲线：最低档 **青蓝 217°** → 最高档 **紫 274°**（`tierHue()`），所有颜色都用
`oklch()` 表达，渐变取本档与相邻低档两个色相，所以拖动时颜色是连续过渡的，不会突跳。

粒子用 **canvas** 画（不是 DOM、也不是 WebGL）：只有 8px 高的一条、颗粒数按宽度算
（约 5 颗/100px），30fps 上限，只在面板打开且处于最高档时才挂载；并且尊重系统的
"减少动态效果"（`prefers-reduced-motion`）—— 那种情况下只画一帧静态粒子。

## 交互

| 操作 | 行为 |
|---|---|
| 点输入框里的 `推理等级 xxx` | 弹出/收起滑轨面板 |
| 点轨道任意位置 | 跳到最近档位并写入 |
| 按住拖动 | 连续换档，圆点吸附到最近档位；写入按档位 id 去重 + 在途合并，不会每帧打后端 |
| ←/→ 或 ↑/↓ | 换一档 |
| Home / End | 到最低 / 最高档 |
| Esc / 点面板外 | 关闭 |

档位列表、当前档位、模型名全部来自官方 `modelDirectories` 服务（与官方模型菜单同一份目录），
档位写入走官方 `directory.select({provider, model, reasoningEffort})`。
DeepSeek 官方适配器当前广告四档：`Off / Low / High / Max`。


## 结构

- `lib/index.js` — 宿主半边：空的 `apply`，只为让 `cordis.patch.yml` 的 `insert`
  行注册成功（本插件不需要任何宿主逻辑）。
- `lib/client.js` — 浏览器端全部实现：座位注册、常驻控件、滑轨面板、目录订阅、档位写入。
- `scripts/build-preview.mjs` — 从 `lib/client.js` 抠出样式与结构，生成
  `preview/panel-preview.html`（浅色/深色 + 各档位 + 拖拽态），浏览器直接看效果。
- `scripts/preflight.mjs` — 重启前的静态预检，按官方 client-modules 的解析规则校验。
- `test/test-client.mjs` — 客户端 bundle 集成测试（jsdom + 真 React 18）。

```sh
node scripts/build-preview.mjs && open preview/panel-preview.html   # 看样式
node scripts/preflight.mjs --profile ~/.dsh/profiles/desktop        # 重启前预检
cd test && npm install && node test-client.mjs ..                    # 行为回归（jsdom）
node scripts/verify-animation.mjs                                    # 动画回归（真 Chrome + 真 React）
```

`verify-animation.mjs` 是唯一能证明"动画真的在动"的一层：jsdom 不算样式、不跑过渡，
所以它只能验证属性写对没有。这个脚本用真 Chrome 挂载真组件，量 `getAnimations()` 与
**中间帧的实际位置**，覆盖"方向键换档""鼠标点轨道（带 1px 抖动）""开面板不滑动"三条路径。

## 模型切换（框只"变长"，对齐 Codex）

点面板里的模型名，**框本身不变宽、不位移，只把高度撑开**，内容从滑块切成模型选择页；
选完自动收回滑块页。整个过程有 300ms `cubic-bezier(.22,1,.36,1)` 的高度过渡。

| | 滑块页 | 模型选择页 |
|---|---|---|
| 宽度 | 300px（**恒定**） | 300px（**不变**） |
| 水平位置 | 与控件右缘对齐（**恒定**） | **不变** |
| 高度 | 内容高度 | 撑开（向上生长） |
| 内容 | 档位名 → 模型名 → 滑轨 | `‹ 返回` + 「选择模型」+ 模型列表（按 provider 分组，当前项打勾；封顶 46vh / 340px 内滚动） |

实现要点：
- 浮层用 **`bottom` 锚定**在控件上方（不是 `top`）—— 高度变化时下缘始终贴着控件，视觉上就是"框往上长"。
- 高度不能只靠内容撑：那样 CSS 过渡不会被触发。所以用 `ResizeObserver` 观察内容高度并**显式同步到 host.height**，过渡才有可插值的两端；`overflow:hidden` 负责动画期间裁剪。
- 视图状态在座位（`EffortSeat`）里，面板通过 `onView` 回调告知切换。

选择走官方 `directory.select({ provider, model })` —— 刻意**不带 `reasoningEffort`**，让官方按该
模型的 `defaultEffort` 处理（档位仍由滑轨单独负责）。列表按 provider 分组，当前项打勾；只有一个模型时模型名按钮禁用。

## 动效

位置动画**不用 CSS transition，改由 `requestAnimationFrame` 补间直接写 DOM**
（`tweenPosition()`）。原因：位置本来是由 React 每次渲染写进 `style` 的，只要 React 因为
任何原因重建了圆点/填充元素，CSS 过渡就不会发生 —— 现象是"点了没动画"，而且从代码上
极难看出来。改成 rAF 补间后，动画与 React 的渲染方式彻底解耦（当前位置存在
`data-esm-pos` 上，元素重建也能接着补）。

| 行为 | 表现 |
|---|---|
| 换档（点击 / 方向键） | **540ms easeInOutCubic** 补间（看得清"挪动"） |
| **拖动** | 圆点**不跟随光标逐像素移动**，只在跨过档位边界时移到对应刻度上（240ms，跟手优先） |
| 打开面板 | 首帧直接落位（不从 0 档滑过来） |
| 颜色 / 柔光 / 档位点透明度 | CSS 过渡（280ms），不受元素重建影响 |
| 最高档 | 青→紫渐变 + canvas 粒子（横向缓漂 / 纵向浮沉 / 透明度呼吸），档位点整体淡出 |
| **圆点到 MAX 那一下** | **爆炸**：从**圆点中心**炸开 30 颗粒子，带阻尼 + 重力、缩小淡出（460ms），颜色跟随本档色相，一次性触发 |

为什么要给足 540ms：官方只有 4 档，一次换档在 264px 轨道上只走约 78px，
短时长（160ms）配常见缓动几乎看不出"移动"。

> **拖动曾经是"零过渡直接落位"**（当时的理由：拖动应当跟手）。结果是用户明确反馈
> "拖动时没有动画、感受不到过渡"。诊断方式：插件把三条路径（首帧 / 直接落位 / 补间）
> 分别计数写进 `localStorage`，再直接从应用自己的 LevelDB 明文里读出计数 —— 最后一条
> 是 `esmSnapDrag`，即"每次都在走直接落位分支"，据此定位到拖动路径。现在拖动也走补间。

## 到 MAX 的爆炸

**圆点滑到 MAX 的那个瞬间**同时发生三件事（都只触发一次，不循环）：

| 部位 | 效果 |
|---|---|
| 圆点 | 先胀后收：`scale(1) → 1.34 → 1`，420ms，`cubic-bezier(.3,1.4,.4,1)`（带过冲，所以是"弹"一下） |
| 轨道 | 一圈 2px 本档色描边从圆点扩散到 2 倍并淡出（冲击环，500ms）—— 挂在**圆点内部**，同心由结构保证 |
| 画布 | 从**圆点中心**炸开 30 颗粒子：150–470 px/s、阻尼 `0.12/s` + 重力 `240px/s²`、`(1-t)²` 淡出，460ms |

要有"爆炸感"而不是"冒个泡"，两个取值关键（都在 `BURST` 里）：**初速要够快**
（圆点直径 28px，最快粒子 150ms 内要飞过 60px）、**角度均匀分布 + 抖动**（纯随机会结块）。

### 坐标与层级：踩了四次

**所有会动的东西（圆点、档位点、冲击环、爆炸起点）必须共用一套坐标**，且**特效画布必须铺满整条轨道**。
这轮为此改了四次，每次都表现为"爆炸看起来不在圆点中心"或"根本没效果"：

1. 圆点按容器百分比定位（不内缩），爆炸起点按"两端内缩"算 → MAX 时偏 14px。
2. 圆点改为内缩定位后，起爆点又用**画布宽度**算 → 再偏 14px。
3. **冲击环曾与圆点不同心**：先漏了垂直居中（`.esm-ring{top:0}` 贴在轨道顶部），补上后横向
   又差了一整条 rail 的宽度（环与圆点的百分比基准不同）。最后不再靠坐标换算 ——
   把环做成**圆点的子元素**（`left/top:50%` + 负 margin 居中），同心从此是结构性保证。
4. **画布被塞在内缩容器 `.esm-railTrack` 里** → 只有 24px 高、宽度也不足，粒子一飞出去就被裁掉
   （最快的粒子 26ms 就出界），肉眼只剩一下微闪 —— 也就是"看不出变化"。

现在的结构：画布是 **`.esm-rail` 的直接子元素**（铺满整条轨道），圆点的百分比也相对整条 rail
解析，所以**画布宽度就是圆点的百分比基准宽度**，起爆点即 `width * percent`，不需要任何内缩换算。

### 位置只能有一个写入方（踩到的僵局）

圆点的 `left` **只由 rAF 补间写**，React 不再给圆点写 `style.left`。两方都写同一属性会互相覆盖：
React 用它渲染时的值盖掉补间的中间值，补间对比自己记账的"当前位置"就以为已到位、直接停住
（实测出现过 `left=100%` 但进度停在 66.7% 的僵局）。补间的位置账本也从 DOM 属性
（`data-esm-pos`）改成了模块内 `WeakMap`。

### 首帧不炸

打开面板时本来就停在最高档，不该爆炸。所以用"跨入"检测（记上一帧的 spark 状态，
只在 `false → true` 时递增爆炸令牌），令牌变化才触发。

## 圆点只跟档位，不跟光标

拖动时圆点的位置**只由档位决定**：指针跨过档位边界的那一刻，圆点移到对应刻度上；
指针在两档之间时圆点就停在刻度上（用户明确不要"实时跟着光标"的效果）。
换档 / 方向键 / 外部改动同样走这条路径。

> 曾经做过"拖动时圆点连续跟随指针 + 对刻度轻度吸附"。它在手感上更"黏"，
> 但用户要的是"圆点停在刻度上"，所以移除了连续跟随（连带 `snapTowards` 吸附函数）。

## 切模型后滑块跑到最左（修过，三层根因）

现象：切换模型后推理等级**保持正确**（仍是 High），但滑块**跑到最左**；重新打开面板后位置
又正常了。这条线索说明问题出在"元素挂载时机"，而不是档位数据。

用最小探针（打开面板 → 设 High → 切模型 → 读圆点几何）逐层挖出三个原因：

1. **React 与补间抢着写 `left`**：React 每次渲染都会把渲染值写进元素样式，而补间用
   rAF 写中间值，两者互相覆盖。→ 现在圆点的 `left` **只由补间写**，React 完全不渲染它。
2. **并存实例的 ref 回调把引用清空**：模型下拉会让面板**实例重建**，老实例卸载时的
   `setKnobRef(null)` 会清掉新实例刚装上的圆点引用 —— 补间于是写到一个不存在的元素上。
   → 每个实例领一个 id 认领自己的元素，`null` 回调只清"自己装的那个"。
3. **effect 不重跑导致新元素拿不到位置**：React 可能**在补间写完之后**再重建一次圆点，
   而那时 `useLayoutEffect` 的依赖（档位/拖动态）没变、不会重跑 —— 新元素永远没有 `left`
   （实测：补间轨迹 0.904→0.686 全部写对了，元素随后被换掉，`style` 变成 `null`）。
   → **落位写进 ref 回调**：元素一挂载就立刻拿到正确位置，不依赖 effect 是否重跑。

验证：`切模型后滑块位置与档位一致` 已作为**硬断言**（切换前后位置差 < 0.05）。

## 代码审查记录（这一轮清掉的东西）

| 类型 | 内容 |
|---|---|
| 死代码 | `MODEL_W`（视图不再改宽度后没人用）、`.esm-measure` 样式（量具改用内联样式）、`settleEase` 与刻度短亮相关代码（按"刻度别折腾"的要求回退） |
| 真 bug | **按压态泄漏**：按下后指针在轨道之外松开时，`rail` 收不到 `pointerup`，圆点会一直卡在"放大 + 光晕"。现在按下期间挂全局 `pointerup`/`pointercancel` 兜底（有断言盯着） |
| 手感 bug | **吸附被算了两次**：拖动时先把指针位置 `Math.round` 成离散档位，再对它套吸附 → 指针停在两档之间时圆点会在刻度间来回弹。现在**视觉位置跟指针（连续值 + 轻吸附）、档位序号仍取最近整数**，两者解耦 |

## 控件宽度必须恒定（不然会推着旁边的控件抖）

档位名长度不一（`High` / `Max` / `Medium`…），若让文字撑开控件宽度，每次换档整个控件都会伸缩，
**右侧官方模型按钮会被推着左右位移** —— 观感就是"字体位置在抖"。

做法：换档前先量出**最宽的档名**（用真实字体挂一个不可见的量具 span 量，不借用组件类名，
免得量具样式被放大到真实控件上），把结果写进 `--esm-level-w` 作为档位文字的 `min-width`。
控件宽度因而恒定；有两条浏览器断言盯着（控件宽度恒定、其后的兄弟元素不被推动）。

## 踩过的三个坑（都已固化成检查）

1. **`exports["./client"]` 缺失 → 整个应用起不来。**
   第一版漏写 `package.json` 的 `exports` 字段。官方 `@deepseek-ai/dsh-client-modules`
   解析客户端 bundle 时要读 `exports["./client"]`，读不到直接抛错，而 `modules` 是
   **required** 插件 —— 结果是 `dsh: startup failed: 1 required plugin did not activate`。
   `scripts/preflight.mjs` 现在会直接报：
   `FAIL  ... 声明了 dsh.client 但 exports 缺少 "./client" → required 插件 modules 激活失败`。

2. **装饰层吃掉指针事件 → "点不到 / 拖不动"。**
   档位刻度那一层 `.esm-ticks` 是轨道下面的兄弟元素，虽然透明但会**拦截指针事件**，
   而它正压在轨道下半部分上。现在装饰层一律显式 `pointer-events:none`
   （集成测试里有一条断言盯着这个）。

3. **座位 `inject` 漏了 `load`。**
   官方座位的注入面是 `{ directory: store, load, select }`；第一版只返回了 store，
   组件里 `directory.load()` 直接抛错。集成测试当场抓到。

另有两个测试自身的坑，记在这里免得再疑神疑鬼：4 档时 High 的滑轨系数是 **2/3**（不是 50%，
那是 3 档的算法）；jsdom/CSSOM 会把 `calc((100% - 6px) * 0.5)` 规范化成
`calc(0.5 * (100% - 6px))`，所以断言要解析系数而不是比对字符串。

## 兼容性

按官方 **0.2.x** 的接口面写就：

- 座位：`ctx.get("slots").inject(name, fn)` + `slots.register({name, id, order, locale, inject}, Component)`；
  `conversation.input.right` 的 kind 是 **list**（可以多插件共存，必须有 `id`）。
- 目录：`ctx.get("modelDirectories").directoryFor(sessionId)` → `{store, load, select}`，
  快照为 `{status, current, groups, failures, pending, error}`，
  模型推理元数据为 `model.reasoning.{efforts[{id,name}], defaultEffort}`。
- 会话 id：`sessions.list` 快照优先读 `list.current`，取不到再按
  `byId[*].retainedBy.mainView > 0` 判定（两代兼容）。

上游若改这几处，插件需要跟着调；项目无构建步骤，改完直接重启即可。

本仓库在官方 **0.2.0-rc.2** 桌面端 / `@deepseek-ai/dsh*` **0.1.5-rc.2** 上验证。
